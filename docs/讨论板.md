## 页面要求

### 帖子的浏览主页

帖子列表流（Feed/List）：

占据页面的主要空间。每一个条目代表一个帖子（主题）。

列表上通常会显示：帖子标题、部分正文或预览图、发帖人昵称、最后回复时间，以及回复数量。这种设计让用户能快速扫视并找到感兴趣的话题。

### 帖子的详情页

1. 底部互动区：

通常固定在屏幕最下方，包含一个输入框，可以快速输入文字回复。

旁边会附带发图片、发表情包快捷按钮。还会有“收藏”、“分享”、“点赞”等操作。


2. 楼层与楼中楼（回复区）：

在主楼下方，其他用户的回复按照时间顺序排列，分别是 2楼（沙发）、3楼（板凳）、4楼（地板）及以后。

楼中楼交互： 如果你点击某一个具体楼层（比如对 5楼 用户的观点有看法），页面会展开一个子区域，显示针对这个 5楼 的所有讨论。在这个小区域里，大家可以互相 @ 进行嵌套回复，而不会打乱整个大帖子的楼层顺序。

## 基础功能

排序、浏览与多媒体互动
顶帖（Bumping）与沉帖： 与匿名版类似，基础的排序逻辑是“最后回复时间”。只要有人回复，帖子就会被重新“顶”回首页第一位；反之则逐渐下沉。

只看楼主： 这是一个极其核心的阅读功能。在连载小说、资源分享、长篇图文直播帖中，开启该功能可以瞬间过滤掉所有其他网友的插话，只显示发帖人的内容。

丰富的媒体支持： 贴吧支持插入多张图片、视频、发起投票（Polls），在移动端甚至支持直接发送语音回复和表情包（神贴、滑稽等经典表情的诞生地）。

## 进阶功能

账号、等级与签到体系
注册与固定ID： 用户必须登录账号发言。虽然可以使用虚拟昵称，但每个人的发言都有固定的账号历史可被追踪，这有效抑制了纯匿名环境下的部分极端行为。

经验值与头衔（Level）： 每个贴吧都有独立的等级系统（通常是1级到18级以上，吧主可自定义各等级头衔）。用户通过每日“签到”（Sign-in）、发帖、回复来获取经验值升级。高等级通常代表在该吧的资历深、活跃度高，这与匿名版追求的“消除身份特权”截然相反。

1. 等级配置表 (level_config)
这张表相当于系统的“规则字典”。它定义了等级的上限、每个等级所需的经验值，以及该等级附带的称号或特权。这张表的数据由管理员在后台配置，通常是静态的。

字段名	数据类型	约束	描述说明
level	INT	主键	具体等级（如 1, 2, 3... 18）
min_exp	INT	非空	达到该等级所需的最低经验值（如 1级为 0，2级为 15）
title_name	VARCHAR(50)	可空	该等级对应的称号（如“初学乍练”、“吧主”）
privileges	JSON	可空	存储该等级解锁的特权配置（如 {"can_upload_img": true, "daily_post_limit": 50}）

2. 用户经验与等级表 (user_level)
这张表记录了每个用户当前的“升级进度”。它会随着用户在系统内的交互（如签到、发帖）而频繁更新。

字段名	数据类型	约束	描述说明
user_id	BIGINT	主键/外键	关联主用户表的用户 ID
current_level	INT	非空，默认 1	用户当前的等级（关联 level_config 表）
total_exp	INT	非空，默认 0	用户累计获取的总经验值
updated_at	TIMESTAMP	自动更新	最后一次经验值变动的时间

3. 经验流水记录表 (exp_action_log)这张表是系统的“账本”。用户获取的每一笔经验值都要在这里留痕。它的作用极大：一是用来给用户展示“经验获取明细”，二是可以用来进行防刷脚本的校验和数据回溯。字段名数据类型约束描述说明
log_idBIGINT主键，自增流水唯一 
IDuser_idBIGINT非空，索引产生交互的用户 
IDaction_typeVARCHAR(50)非空动作类型枚举（如 SIGN_IN 签到, POST_THREAD 发帖, REPLY 回复）
exp_deltaINT非空本次交互增加或扣除的经验值（如 +5, -10）
target_idBIGINT可空关联的业务 ID（比如是因为回复了 ID为 1024 的帖子获得了经验，就填 1024）
created_atTIMESTAMP默认当前时间动作发生的时间
Gemini 说
既然我们刚才聊到了贴吧的“等级与经验值”体系，如果您打算自己设计一个类似社区论坛或游戏的“升级系统”，在数据库层面上，一个健壮的设计通常不会把所有数据塞进一张表里。

为了保证系统的可扩展性和后期维护，我们通常需要设计 三张表 来协同工作：规则配置表（定义升级规则）、用户状态表（记录用户当前等级）以及经验流水表（记录经验怎么来的）。
