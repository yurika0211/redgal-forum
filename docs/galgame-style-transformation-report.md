# Rubedo 全项目 Galgame 风格改造报告

## 1. 结论先行

这个项目已经具备改造成 Galgame 风格二次元站的基础条件，但当前仍停留在“前后端联调看板”阶段，还不是一个完整的内容型社区产品。

从仓库现状看：

- 前端已经用 React 19 + TypeScript 起步，但页面入口仍集中在 `frontend/src/App.tsx`，本质上是一个接口联调首页。
- 后端已经拆出了 `auth`、`user`、`article`、`forum`、`wall`、`luckybot` 六个模块，业务骨架是对的。
- 数据库设计已经覆盖文章三层可见度、匿名论坛、展示墙审核、Bangumi 导入、Luckybot，会比普通论坛更容易做出“Galgame 社区”的产品味道。

因此，正确方向不是“换几张动漫背景图”，而是把整个项目升级成一个有统一世界观、统一叙事语气、统一交互节奏的视觉小说式社区。

我对这个项目的判断是：

- 后端业务模型已经够用，可以支撑第一阶段 Galgame 化。
- 最大短板在前端信息架构、设计系统、页面叙事和内容标签体系。
- 如果只改样式，不改页面结构和内容模型，最后只会变成“套了二次元皮的普通论坛”。

## 2. 当前项目现状

### 2.1 前端现状

目前前端已经有一定氛围感，但还不是 Galgame 风格站点：

- `frontend/src/App.tsx` 直接把健康检查、登录、用户、文章、讨论串堆在一个页面里。
- `frontend/src/App.css` 已经有暗色玻璃、渐变、圆角卡片，但整体更像技术产品 landing page，而不是视觉小说风格社区。
- `frontend/package.json` 只有 `react` 和 `react-dom` 运行时依赖，说明项目还没有路由、服务端状态管理、动画层、主题层这些真正的站点骨架。

这意味着现在最需要的不是“继续堆样式”，而是先把单页联调面板升级成多页面产品。

### 2.2 后端现状

后端路由已经具备完整站点雏形：

- `GET /api/v1/health`
- `POST /api/v1/auth/login`
- `GET /api/v1/users/me`
- `GET /api/v1/articles`
- `GET /api/v1/forum/threads`
- `GET /api/v1/wall`
- `POST /api/v1/luckybot/chat`

这套模块划分很适合 Galgame 风格社区，因为它天然能分成几条“体验线路”：

- 公开访客线：首页、公开文章、展示墙
- 成员互动线：论坛、匿名版、回复
- 个人角色线：个人主页、Bangumi 收藏
- 情绪陪伴线：Luckybot

### 2.3 数据库现状

`DB/schema.sql` 和 `DB/database_design.md` 已经给了非常好的产品基础：

- `visibility_level` 支持 `public`、`members`、`private`
- 论坛支持普通版和匿名版
- 展示墙有投稿、媒体、审核流
- Bangumi 有条目缓存和同步任务
- 用户有头像、签名、Banner、个人可见度

这说明第一阶段根本不需要重做数据库，只要补充少量“Galgame 表达字段”，就能快速进入产品化。

## 3. 改造目标

建议把 Rubedo 定位成：

**“校园社团记忆站 + Galgame 讨论社区 + 视觉小说式个人主页”**

这个定位比“二次元论坛”更清晰，因为它同时解释了三件事：

- 为什么会有公开文章和感悟区
- 为什么会有论坛讨论和匿名版
- 为什么展示墙和个人主页应该非常有氛围

用户进入站点后应该获得的感觉不是“我来到一个论坛”，而是：

- 我进入了一个有故事感的社团站
- 每个版块像视觉小说的不同章节
- 每个用户主页像角色设定档
- 每篇感悟像回忆录或通关后日谈

## 4. 推荐的整体风格方向

不要把全站做成杂糅的“粉蓝紫霓虹大拼盘”。Galgame 风格站点最怕主题不统一。

建议统一世界观为：

**“放学后社团活动室 + 回忆相册 + 校园黄昏”**

基于这个主方向，再拆成三个子主题：

### 4.1 公共首页主题

- 关键词：晚霞、窗边、风铃、纸张、公告栏
- 用途：首页、登录页、公开文章入口
- 情绪：欢迎、轻柔、带一点青春感

### 4.2 讨论区主题

- 关键词：部室、对话框、章节分支、任务板
- 用途：论坛列表、帖子详情、匿名讨论区
- 情绪：活跃、偏剧情推进感

### 4.3 回忆区主题

- 关键词：相册、拍立得、旧纸、时间轴、留声机
- 用途：展示墙、个人主页、Bangumi 收藏页
- 情绪：沉浸、怀旧、偏“通关后后劲”

## 5. 前端需要怎么改

### 5.1 先把单页改成真正的站点骨架

建议优先补下面这些基础设施：

1. 引入路由
2. 把 `App.tsx` 从联调看板拆成页面外壳
3. 建立统一主题 token
4. 建立页面级布局和共享组件层

推荐的页面结构：

```text
/
/forum
/thread/:id
/memories
/profile/:username
/bangumi
/luckybot
/admin
```

推荐的目录结构：

```text
frontend/src/
  app/
  pages/
  features/
  shared/
  entities/
```

如果不先做这一步，后面所有 Galgame 风格组件都会继续堆在一个文件里，很快失控。

### 5.2 建立设计系统，而不是散落样式

建议用 CSS Variables 做主题层，不要让业务组件直接写颜色值。

至少抽出这些 token：

- 背景层：`--bg-base`、`--bg-panel`、`--bg-overlay`
- 文本层：`--text-main`、`--text-soft`、`--text-kicker`
- 强调层：`--accent-pink`、`--accent-gold`、`--accent-sky`
- 装饰层：`--line-soft`、`--glow-strong`、`--shadow-card`
- 圆角与间距：`--radius-panel`、`--radius-pill`、`--space-1` 到 `--space-8`

建议字体不要继续停留在普通系统字体：

- 标题层：自托管 `LXGW WenKai` 或 `ZCOOL XiaoWei`
- UI 层：自托管 `M PLUS Rounded 1c` 或其他圆润风格字体
- 长文正文：保持高可读性，不要使用过度花哨字体

### 5.3 组件风格需要从“卡片展示”升级为“视觉小说界面”

建议优先建设这些组件：

- `SceneShell`：统一背景层、纹理层、漂浮装饰层
- `ChapterHeader`：章节标题，替代普通 `h2`
- `RouteTabs`：像 Galgame 分支选项的页签
- `CharacterCard`：个人主页的角色档案卡
- `ThreadCard`：讨论串卡片，支持封面、情绪标签、剧透提示
- `ReplyBubble`：帖子回复气泡，替代普通论坛楼层
- `MemoryPolaroid`：展示墙拍立得卡片
- `MusicBanner`：可选的 BGM/氛围提示条
- `EmotionBadge`：如“刀子预警”“糖度高”“后劲很大”“校园系”
- `AchievementBadge`：社团称号、路线成就、收藏勋章

这些组件会直接决定站点有没有“Galgame 语言”，比单纯调色重要得多。

### 5.4 页面级改造建议

#### 首页

首页不要再当接口总览页，要变成世界观入口：

- 第一屏：站名、标语、活动入口、精选内容
- 第二屏：热门感悟、近期讨论、展示墙精选
- 第三屏：Luckybot 入口，做成看板娘对话窗
- 第四屏：社团时间轴、活动预告、最近更新

首页的任务是“拉用户进入氛围”，不是“展示 API 已连通”。

#### 论坛列表页

建议做成“章节选择器 + 剧情卡片流”：

- 版块切换像章节目录
- 讨论串卡片有封面、标签、回复数、热度状态
- 匿名版需要明确氛围区分，但不能让人误以为是完全失控区

#### 帖子详情页

建议主楼和回复区做视觉区分：

- 主楼保持阅读性，样式克制
- 回复区采用对话气泡或 ADV 对话框语言
- 匿名楼层可生成站内化名，如“观测者 07”“风纪委员 A”

#### 展示墙

这是全站最适合做出 Galgame 氛围的模块：

- 用相册、时间轴、拍立得、灯箱浏览
- 支持故事短摘、地点、日期、活动标签
- 审核通过内容可以做“社团回忆卷”

#### 个人主页

不要做成传统“个人中心”，而要做成“角色档案页”：

- Banner 像角色路线封面
- 头像区域像立绘卡
- 签名像角色台词
- Bangumi 收藏像作品书架
- 发文列表像个人章节目录

#### Luckybot

这个模块不要做成普通聊天页，建议定位为：

**“站内看板娘 / 部室 AI 助手 / 情绪陪聊角色”**

也就是说，Luckybot 在视觉上应该更像 Galgame 对话场景，而不是客服聊天框。

## 6. 后端和数据模型需要补什么

当前后端足够支撑第一阶段，但如果想真正做出 Galgame 味道，建议补一些轻量字段。

### 6.1 文章模块

建议给 `articles` 增补以下字段：

- `cover_image_url`
- `mood_tag`
- `spoiler_level`
- `subject_id` 或外部作品关联
- `quote_text`
- `published_scene`

这样文章卡片才能从“普通帖子”升级成“通关感想卡”。

### 6.2 论坛主题帖

建议给 `forum_threads` 增补：

- `cover_image_url`
- `topic_mood`
- `contains_spoiler`
- `featured_subject_id`
- `route_label`

这能让论坛列表出现更明确的视觉标签和情绪标签。

### 6.3 展示墙

建议给 `wall_entries` 增补：

- `event_date`
- `album_title`
- `location_label`
- `excerpt`
- `music_url` 或 `bgm_note`

展示墙本质上就是最适合做“社团回忆录”的地方，字段太平会浪费它。

### 6.4 用户资料

建议给 `users` 增补：

- `profile_theme`
- `character_title`
- `favorite_tags`
- `profile_card_style`
- `favorite_subject_id`

这会让个人主页从资料表单变成角色设定页。

### 6.5 枚举和标签字典

为了避免所有 Galgame 元数据都塞进自由标签，建议增加几个轻量字典：

- `mood_tags`
- `scene_tags`
- `spoiler_levels`
- `site_events`

原则是：高频展示字段结构化，长尾内容继续用普通标签。

## 7. 管理后台和运营层也要同步改

Galgame 风格站点不能只靠前台页面，后台运营也要跟上。

建议后台增加：

- 首页 banner 和季节主题配置
- 活动专题配置
- 标签字典管理
- 展示墙精选位管理
- Luckybot 人设文案管理

建议内容运营增加：

- 剧透分级规范
- NSFW 和违规内容边界规范
- 作品标签规范
- 展示墙投稿模板
- 每月主题活动

否则前台会很好看，但内容会很快变乱。

## 8. 技术路线建议

### 8.1 前端依赖建议

目前前端依赖过轻，建议按下面顺序补：

- 路由：`react-router-dom`
- 服务端状态：`@tanstack/react-query`
- 轻量全局状态：`zustand`
- 动画：`motion`

不建议主站一开始直接引入重型 UI 框架，否则很容易把二次元氛围冲淡。

如果后续做管理员工作台，可以在 `admin` 路由单独接常规组件库。

### 8.2 媒体与性能

Galgame 风格很依赖图像和背景，但这也最容易把站点拖慢。

建议从一开始就做：

- 首页背景图、角色图、展示墙图片分级加载
- WebP/AVIF 资源优先
- 统一封面裁切比例
- 移动端关闭高成本装饰动画
- 背景层和内容层分离，防止滚动掉帧

### 8.3 组件边界

建议按下面的责任划分：

- `pages/` 负责页面组装
- `features/` 负责文章流、论坛流、展示墙、Bangumi、Luckybot 等业务模块
- `shared/ui/` 放风格组件
- `entities/` 放用户、文章、主题帖等实体展示逻辑

## 9. 推荐分阶段推进

### 第一阶段：站点骨架重建

目标：从联调首页升级成多页面站点

交付内容：

- 路由层
- 布局层
- 主题 token
- 首页、论坛列表、个人页基础壳

### 第二阶段：Galgame 视觉语言落地

目标：建立真正统一的站点观感

交付内容：

- 背景系统
- 标题系统
- 章节式导航
- 对话框风格回复
- 展示墙相册视图

### 第三阶段：内容模型增强

目标：让二次元风格不是空壳

交付内容：

- 情绪标签
- 剧透等级
- 封面字段
- 角色称号
- 站内活动专题

### 第四阶段：高级沉浸功能

目标：拉开与普通论坛的差距

交付内容：

- Luckybot 人设化
- 首页活动剧情化入口
- Bangumi 书架视觉升级
- 季节主题切换

## 10. 这几个坑最好提前避开

### 10.1 不要只做“粉色 + 发光”

如果只改颜色，最后会像廉价二次元皮肤站，缺少真正的作品感。

### 10.2 不要过早上 Live2D

Live2D 很吸引人，但它不是第一优先级。没有完整页面叙事和内容体系时，Live2D 只会变成高成本装饰物。

### 10.3 不要为了花哨牺牲阅读性

论坛、感悟、展示墙本质上都是内容产品，正文可读性必须高于装饰性。

### 10.4 不要忽略版权和审核

Galgame 圈内容常常天然靠近版权图、敏感图和剧透内容。站点越有氛围，越容易让用户默认“什么都能发”，这一点必须靠审核流、标签规范和站规收住。

## 11. 最推荐的实施顺序

如果要我给出最务实的一条路线，我会建议：

1. 先把前端从 `App.tsx` 单页拆成站点骨架
2. 再建立统一主题和核心风格组件
3. 优先改首页、论坛、展示墙、个人页四个核心页面
4. 然后给文章、讨论串、展示墙补 Galgame 元数据字段
5. 最后再做 Luckybot 人设化和季节活动系统

这条顺序的好处是：

- 改动风险低
- 每一阶段都有可见成果
- 不会前端样式和后端数据模型互相等待

## 12. 最终判断

Rubedo 这个项目非常适合做成 Galgame 风格二次元站，而且不是那种“只能做外观”的项目。

它真正的优势在于：

- 有公开感悟区，适合做成“通关后日谈”
- 有论坛和匿名版，适合做成“章节讨论区”
- 有展示墙，适合做成“社团回忆录”
- 有 Bangumi，适合做成“作品书架”
- 有 Luckybot，适合做成“看板娘入口”

所以你的目标不应该是“做一个二次元论坛皮肤”，而应该是：

**做一个带视觉小说叙事感的 Galgame 社区站。**

如果后续要真正开始动手，建议先从前端站点骨架、主题系统和四个核心页面改造开始，这会是投入产出比最高的一步。
