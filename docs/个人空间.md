空间主卡在最上面，下面的展示内容大部分不是卡片，然后有动画、书籍还有游戏的选项，这些就是拉一个条，然后下面排列作品的图片，然后有卡片的是用户的时间胶囊还有好友这些模块，整体的布局就是，左边是作品，右边是好友还有时间胶囊等功能性卡片，然后也支持直接导入bangumi的数据，提供作品id就可以导入了，然后用户有自己的日志区，可以选择公开还是仅自己可看，文章支持直接上传图片，然后暂时使用markdown来编写格式。

请作为一名前端/全栈开发专家，帮我开发一个“个人空间（Personal Space）”页面。请仔细阅读以下需求，并按模块逐步给出实现思路和代码。

# 一、 整体页面布局 (Layout)
1. **顶部区域**：横向铺满的“空间主卡（Profile Header Card）”，展示用户基础信息。
2. **下方主体内容区**：采用左右分栏布局。
   - **左侧内容区（占主导，如 70% 宽度）**：无边框或弱化卡片感，主要用于沉淀和展示核心内容。
   - **右侧功能区（占次要，如 30% 宽度）**：使用标准的卡片UI（Card），存放交互性模块。

# 二、 模块详细需求
## 1. 左侧：作品展示区 (Media Showcase)
- 包含三个子版块：动画、书籍、游戏。
- **UI设计**：每个版块顶部是一个带有微动画效果的“分类标题条（Section Bar）”，标题条下方使用网格（Grid）或横向滚动（横向瀑布流）排列作品的封面海报图。整体去除繁重的卡片包裹感，突出作品图片本身。
- **功能点 (Bangumi API 集成)**：支持用户点击“导入”，输入 Bangumi 的作品 ID，前端需请求 Bangumi API 自动获取作品的海报和基础信息并渲染展示。

## 2. 左侧：个人日志区 (Journal/Blog)
- **展示形式**：按时间线排布的文章列表。
- **编辑功能**：
  - 接入 Markdown 编辑器（如 Vditor、MdEditor 等）进行文章撰写和格式渲染。
  - 支持直接在编辑器中上传图片。
- **权限管理**：发布日志时，需提供“公开（Public）”和“仅自己可见（Private）”的状态切换按钮，并根据状态在界面上展示对应的权限图标。
- **注意**：日志的这个边界界面需要单独做一个页面，这样便于使用者去编辑

## 3. 右侧：功能组件区 (Functional Cards)
使用清晰的卡片化UI（Card Component）自上而下排列：
- **时间胶囊 (Time Capsule) 卡片**：这个只是用来标记用户行为的，添加一个新的作品，换个头像或者换个个性签名都需要在这里记录一下。
- **好友列表 (Friends) 卡片**：展示好友头像列表
- **好友列表**：给每个人生成一个六位数的用户id,这个id是用用户名根据redgal这个密钥进行计算然后取后六位得到的，然后可以根据这个密钥去搜索对应的用户，进入别人的页面之后，大部分内容和本人的页面差不多，就是缺少了编辑权限，但是增加了添加好友的按键和逻辑，好友申请需要对方同意之后才能进行，然后添加好友之后就可以进行私信，私信是需要单独进一个页面，这个注意模仿推特的聊天就可以了。
